## 怎么启动

电脑需要 Node.js 24 或更新版本。双击本目录的「启动前后端.cmd」。脚本会在缺少依赖时安装依赖，然后构建页面并启动服务。看到提示后打开 http://127.0.0.1:8000/，保持命令窗口开启，Ctrl+C 结束服务。

也可在本目录运行：

```cmd
npm.cmd ci
npm.cmd run build
npm.cmd start
```

若需要修改前端并实时刷新：一个窗口执行 npm.cmd run server，另一个执行 npm.cmd run dev。Vite 的 /api 请求代理到 127.0.0.1:8000。生产预览建议使用 npm start 的 8000 地址，避免把没有代理的 npm run preview 当作全栈服务。

## 页面操作

默认选择 API 模式，新的配置存储键为 zhixi-api-config-v2，以免旧浏览器缓存中的 mock 模式遮蔽本次接入。也可在「偏好与连接」确认真实后端、基础地址 /api/v1、健康检查 /health。页面上的 API 标识表示请求模式，实际连接成功以健康检查和业务响应为准。

支持问题：基尔霍夫电压定律、用导数判断函数单调性、牛顿第二定律及它们在 app 资料库中的别名。未知主题明确返回 422，不会用电路示例冒充回答。选择诊断答案 → 生成路径 → 查看概念讲解 → 标记步骤完成 → 新题复测。

## 学习诊断 Agent（2026-11-07 新增）

原先只有 `/chat` 单次模型调用，业务接口全是固定题库。本次补上分环节 Agent 编排：每个环节有独立提示词、结构化校验、修复重试和本地降级，模型不再直接决定分数或答案。

### 七个环节

| stage | 环节 | 模型输出 | 服务端职责 | 失败降级 |
|---|---|---|---|---|
| intent | 理解问题 | topicId、置信度、匹配依据 | 校验主题在资料库内；低置信度先尝试本地别名匹配 | 本地别名匹配 |
| diagnose | 生成诊断短测 | 2 道单选、4 选项、答案下标、关联节点 | 隐藏答案、校验节点存在、题干预览去重 | 主题自带首测题 |
| grade | 评分与归因 | 薄弱节点与原因、建议 | 服务端计算正确率；限制薄弱点只能来自错题节点 | 原规则归因 |
| plan | 规划学习路径 | 3-5 步（候选不足时用全部候选） | 步骤 id、节点 id 必须来自候选路径 | 原路径过滤逻辑 |
| explain | 生成概念讲解 | 讲解正文 | 校验长度与节点存在；只喂该节点来源 | 原资料库讲解 |
| retest | 生成迁移复测 | 2 道与首测不同的题 | 校验题干不重复、重点节点范围、答案隐藏 | 主题自带复测题 |
| tutor | 引导式答疑 | 回答正文 | 先检索命中主题的节点、来源、路径作为上下文 | 未配置 503；调用失败 502 |

提示词集中在 `server/agent/prompts.mjs`（`PROMPT_VERSION = agent-v1`），统一约束：只使用给定知识库、只输出 JSON、不编造来源、不泄露答案、不虚构学生数据。

### 执行机制

代码分层：

- `server/agent/config.mjs`：环境变量与注入配置解析。
- `server/agent/llm.mjs`：OpenAI 兼容客户端，超时、429/5xx 重试、代码围栏剥离。
- `server/agent/knowledge.mjs`：知识库工具（主题匹配、图谱、来源、题库、路径、答案归一化）。
- `server/agent/schemas.mjs`：纯函数校验与归一化，错误文本用于修复提示词。
- `server/agent/orchestrator.mjs`：环节编排、trace、修复重试、本地降级。
- `server/agent/prompts.mjs`：七环节提示词 + JSON 修复提示词。

单环节执行链：**调用模型 → 解析 JSON → schema 校验 → 失败时用修复提示词重试 1 次 → 仍失败回退本地规则**。模型异常不会让业务接口 500；降级会记录在响应的 `agent.stages` 与 `agent.degraded` 中。

会话现在会持久化模型生成的题目（含答案、解析、关联节点）到 `server/.data/sessions.json`，重启后仍可提交与复测；公开响应始终不包含 `answer / answerIndex / explain / tests`。

### 配置

在 `server/.env` 中配置（密钥只在服务端）：

```ini
LLM_BASE_URL=https://your-provider.example/v1
LLM_MODEL=your-model
LLM_API_KEY=
# 可选
AGENT_ENABLED=true
LLM_TIMEOUT_MS=30000
LLM_TEMPERATURE=0.2
LLM_MAX_TOKENS=1600
LLM_MAX_RETRIES=1
```

未同时配置 `LLM_BASE_URL` 与 `LLM_MODEL` 时，`agent.mode = "local"`，全部环节走本地规则，行为与接入前一致。

## 函数绘图工具（2026-11-08 新增）

新增「函数绘图」页（侧栏位于「学习路径」之后）。该页只调用确定性工具，不经过模型，也不需要模型 Key：服务端用 mathjs 编译表达式，在定义域内固定采样 241 点，同时生成服务端 SVG 与纯文本；前端用 function-plot 渲染交互图，并可下载服务端 SVG。

后端实现位于 `server/tools/functionPlot.mjs`，为纯函数、无副作用：相同输入必定返回相同 SVG 与文本。未引入 Fastify，路由仍挂在原生 `node:http` 的 `server/index.mjs` 上。

### GET /api/v1/tools

返回已暴露的确定性工具列表：

```json
{"tools":[{"name":"function.plot","title":"函数绘图","description":"根据数学表达式在给定定义域内采样 241 点，返回服务端 SVG 与纯文本；数据点由服务端计算，不接受客户端提交。","render":"svg+text"}]}
```

### POST /api/v1/tools/function.plot/invoke

请求体：

```json
{"expression":"sin(x)","domain":[-10,10]}
```

- `expression` 必填，字符串，长度 ≤ 200。只允许数字、`x`、`+ - * / ^ ( )`、空格，以及 `sin/cos/tan/log/ln/sqrt/abs/exp/pi/e`。`ln` 会被改写为 mathjs 的自然对数 `log`。
- `domain` 可选，默认 `[-10,10]`；必须是两个有限数值，绝对值 ≤ 1e6，且下限小于上限。

成功响应（`durationMs` 为本次采样与渲染耗时）：

```json
{
  "ok": true,
  "durationMs": 3,
  "result": {
    "artifact": {"kind": "function", "expression": "sin(x)", "domain": [-10, 10]},
    "svg": "<svg xmlns=\"http://www.w3.org/2000/svg\" ...>...</svg>",
    "text": "y = sin(x)\nx ∈ [-10, 10]\n采样 241 点 · 非有限值断开"
  }
}
```

参数非法（表达式字符越界、超长、无法解析、定义域反向/越界/非有限，或定义域内没有可绘制的有限实数值）返回 422 `{"detail":"..."}`；方法错误返回 405 `{"detail":"不支持该请求方法"}`。SVG 包含坐标轴、网格、曲线与标量函数值；非有限值或极点处会断开路径。

本地验证示例：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/tools
Invoke-RestMethod -Method Post -ContentType 'application/json' `
  -Uri http://127.0.0.1:8000/api/v1/tools/function.plot/invoke `
  -Body '{"expression":"sin(x)","domain":[-10,10]}'
```

## 接口

GET /api/v1/health 返回引擎和主题列表。
POST /api/v1/diagnose/start 创建独立会话，返回图谱、来源与不含答案的题目。
POST /api/v1/diagnose/submit 在服务端评分，生成薄弱点和相关路径。
POST /api/v1/diagnose/retest 创建新会话并返回 app 中的另一套题，需先提交当前诊断；每个主题仅有首测与复测两套题。
POST /api/v1/learn/explain 返回 app 中的概念说明、前置依据、分节学习资料。
GET /api/v1/graph/:sessionId 和 /sources/:sessionId 查询会话资料。
POST /api/v1/chat 为可选模型代理，未配置时明确返回 503。
GET /api/v1/tools 返回确定性工具列表；POST /api/v1/tools/function.plot/invoke 执行函数绘图，无需模型 Key。

会话保存在 server/.data/sessions.json，重启可恢复。此目录及 server/.env 已加入 .gitignore。前端历史和学习完成标记仍保存于浏览器，尚未同步到服务端；图谱人工覆盖仍是前端状态。

## 模型接入边界

当前已跑通的是「app 本地资料与规则引擎」经真实 HTTP 服务接入前端，不等于已经接入外部 AI 大模型。桌面版原有 llm.request 是 WebView2 消息协议，不能直接在普通浏览器调用。

需要外部模型时，将 server/.env.example 复制为 server/.env，填写 LLM_BASE_URL、LLM_MODEL、LLM_API_KEY 并重启服务。密钥仅保留在后端；/chat 对接兼容 Chat Completions 的服务。当前前端主流程使用题库诊断，不调用 /chat，不会自动变为无限学科诊断。生成式诊断与教师方案需要后续接入对应前端流程和校验规范。

## 部署

GitHub Pages 只能托管 dist 中的静态前端，不能运行 Node 后端。需要远程使用时，将后端部署到支持 Node.js 的服务，配置 HTTPS 域名、认证与存储，然后把前端 VITE_API_BASE 设置为该域名的 /api/v1，并在 CORS_ORIGINS 中加入实际前端 origin。默认服务只监听 127.0.0.1，适用于个人本地联调，未包含公网认证、速率限制和多用户隔离。
